## Workspace coordination and rollback ownership

**D-TXN-1 — Provisional. K-TXN:** one Workspace coordinator owns explicit nesting, implicit-operation policy, enlisted file identities and outcome receipts. A Database or cursor does not independently resolve a Workspace transaction. Microsoft's DAO documentation describes Workspace-wide scope and inner commits that remain reversible through outer rollback.[^workspace]

Maintain explicit transaction frames and separate statement/edit frames. On first mutation in a rollback scope, retain the necessary prior image, allocation/reference changes and catalog state; avoid logging an unchanged page repeatedly within that scope. Successful child commit merges retained changes and rollback obligations into its parent, preserving the earliest image needed by an outer rollback. Child rollback restores the policy-selected scope and discards its changes, retaining obligations still required by surviving outer scopes. Frames are memory/spill structures, not independently durable savepoints or an own WAL. Ordinary uncommitted reads use the owning transaction's private view; other readers follow I-09's visibility policy.

Prefer current-level logical resolution as the documented nesting baseline; R-TXN-1/TXN-NEST selects exact scope and depth limits. II-08 separates `ScopeBefore` entries from accepted semantic/generated-value receipts and private page revisions. An inner merge preserves the earliest image required by its parent; failed statement restoration uses that statement's before-image rather than the outer transaction's. Database bindings and native file participants are distinct, including aliases to one file. TXN-VIEW/SUPPORT determine which operations enlist without deriving transaction visibility from a cursor's Transactions capability. A statement rollback boundary is not a user-visible BeginTrans level. Close events, including Workspace and clone closure, reach the coordinator. Public objects may remain referenced after their underlying resources close; their subsequent errors/state must match the surface contract.

For multiple databases, enlist by verified identity, reserve resources and acquire known participants in stable order where this does not change observable behavior. Late enlistment uses explicit conflict handling, never an internal latch held while waiting. Successful resolution publishes the required in-process views coherently; partial-failure publication follows the observed outcome policy. No cross-file durable atomicity is inferred from this coordination, and no two-phase-commit side format is introduced. The owned `ResolutionAttempt` retains a participant-specific effect vector through failure, an empty commit, reentry and result marshalling. Logical frame/view transitions are recorded alongside native effects; a late error cannot revive a resolved frame. Publication uses reserved metadata and deferred release outside latches. TXN-MULTI/CLOSE select the public continuations and which scopes remain usable.

Phase 1 has separate Workspace/Connection lockers and concurrent private change sets. A transaction does not own a file-wide writer gate until it ends. Conflicts use ACE's page or record granularity and finite retry settings, then its observed error. R-TXN-1/TXN-LOCAL decides that policy. At publication, II-09's short resolution gate protects fresh-base reconstruction: accepted effect-free deltas are applied over the newest committed base without repeating callbacks or generated values. A local private rollback removes only its owner's changes; it cannot restore an old whole page over another owner's commit. Later external sharing adds native lock roles to this same reconstruction. Fresh-view admission closes before preserving old sources. On successful publication, release that hold and the publication gate before draining deferred interface releases; foreign destruction can open a new view.

## Statement failures are a separate policy

**Preferred provisional rule:** where `dbFailOnError` applies, retain statement undo so a failed action can reverse that statement's successful changes while preserving the enclosing transaction as required. QueryDef.Execute's documentation supports rollback; Database.Execute's option table contradicts its own remarks.[^execute] R-SQL-2/R-TXN-1 settle the flag × explicit-transaction × operation × failure-class matrix before this rule is generalized. Without the flag, a native-classified candidate failure can instead select `SkipCandidate`: settle that candidate's database work and generated-value disposition, retain its effects, and continue from the next protected enumeration occurrence. Earlier accepted rows remain under the operation's normal policy. Skipping adds no successful mutation and publishes no error for the skipped failure; the final affected count and prior error state follow the successful-call policy. A non-skippable class or failed/uncertain settlement selects `StopAction`, with the coordinator's actual reversal or partial outcome. R-SQL-2/SQL-CONTINUE checks success–blocked–success and all-blocked cases, both Execute surfaces, flags and transaction depths. DDL, generated identities, counts and error collections remain part of the same investigation.

Rollback restores the relevant private and already-persisted state through an explicit protocol; releasing buffers is sufficient only if no covered persistent effects occurred. TEMP exhaustion is especially discriminating: DAO documents commit after exhaustion as potentially preserving an indeterminate subset, while rollback has different behavior.[^workspace] An internal uncertain state must retain progress and admissible next operations until the boundary can report the evidenced result. Do not replace it with a reassuring rollback success or a novel public error convention.

## Preferred provisional write ordering

**D-WRITE-1 — Provisional.** Start with **one final stored image per changed page per publication unit** under the initial exclusive external lease. Keep explicit uncommitted changes private and publish an operation or outer commit through a resolution gate; several lockers can still own private changes. R-FMT-2 supplies structure rules, R-TXN-1 supplies logical outcomes and write timing, and R-CRASH-1 selects the order and any required repeated-image fallback. This is an in-place native writer, with no WAL or authoritative side database.

**Figure F-10 — independent transaction dimensions.**

| Dimension | State retained |
| --- | --- |
| Logical scope | Explicit depth, active statement/edit boundary, enlisted participants and permitted next operations. |
| Visibility | Each locker's private revisions, committed-base generation and the native-selected reader policy. |
| Persistence | Ordered effects attempted/completed, partial/uncertain effects, required flushes and their completion. |
| Public outcome | Returned success/error, affected counts, error collection and acknowledgement frontier. |

The preferred candidate orders submission and required completion as follows. It does not establish power-loss persistence order or claim a healthy graph at every interruption.[^flush]

| Phase | Preferred provisional candidate | Experiment that confirms or changes it |
| --- | --- | --- |
| 1. Prepare and rebase | Retain accepted values and scope-before images; acquire the resolution gate, validate local grants and rebuild final data/LV, index, catalog and map images over the latest committed base. Reserve preservation and outcome storage before native effects. | TXN-LOCAL/TXN-TEMP and R-FMT-2 decide conflicts, rollback and allocation behavior; R-CRASH-1 records the resulting program. |
| 2. Initialize new targets | Extend only where required; write each new LV, data, map or disconnected index page with its final contents before publishing a pointer to uninitialized bytes. | R-FMT-2 and R-CRASH-1 compare extension, initialization and map order. |
| 3. Change rows, then indexes | Write final existing data/LV reference pages, then final index/ancestor pages. An indexed key update writes the leaf once. | **CRASH-ORDER-DATA** is the starting direction; **CRASH-ORDER-INDEX** tests the reverse order. |
| 4. Publish catalog references | Write operation-required final catalog/descriptor images after their new targets are initialized, composing aliases on the same physical page. | R-CAT-1 and R-CRASH-1 select catalog row/index/root order. |
| 5. Publish final existing maps | Prefer one composed map image after affected old references have been withdrawn, then perform any admitted tail truncation. A map can combine allocation and retirement. | R-FMT-2/R-CRASH-1 compare named MAP-BEFORE and MAP-AFTER variants; MAP-AFTER is the starting candidate. Map-after can temporarily expose new references before their ownership bits; map-before can make old storage free early. Neither cut is declared safe by construction. |
| 6. Resolve native and logical state | Install the selected logical view/frame result and reproduce any evidenced native state transition. There is no invented commit word or needs-repair flag. | R-TXN-1 and R-CRASH-1 decide visibility, error, marking and survival behavior. A required intermediate marker or repeated map image selects the fallback program. |
| 7. Complete the selected durability intent | Ordinary commit starts without an unconditional forced flush. `dbForceOSFlush` additionally completes the supported flush sequence before its required success boundary. | TXN-FLUSH-LIVE and paired interrupted cases decide timing, ordinary/forced survival and acknowledgement. |

A physical page may hold several logical structures. Compose its final patches together; do not write independent stale map or catalog versions over one another. The simple candidate can expose incomplete intermediate graphs even when its final graph is correct. **CRASH-ORDER-REPEAT** retains two explicit fallback subcases for an indexed change: remove old entry → row → add new entry (**CRASH-ORDER-REPEAT-REMOVE**), and add new entry → row → remove old entry (**CRASH-ORDER-REPEAT-ADD**). Required repeated map, header or catalog transitions use the same general compiler. Evidence selects them; they are not the starting cost paid by every DAO edit.

II-03 provides immutable stored-image transfers and preserves required old native backing before overwrite, including a reader whose old-page load has not yet started. Complete-page requests are the initial transfer unit, with a span-capable interface; a 4096-byte request is not assumed atomic. R-FMT-2/R-CRASH-1 select any required spans and the relevant failure model.

Write timing is an independent question. **TXN-FLUSH-COMMIT** tests deferred native publication at explicit outer commit; **TXN-FLUSH-OP** tests publication by the end of each implicit operation; **TXN-FLUSH-BEHIND** tests an implicit operation returning with owned pending writes and the later events that drain them. The first construction uses commit-time explicit publication and operation-end implicit publication. An observed write-behind result changes the owned pending-work and acknowledgement policy; it does not authorize an unowned task or silent replay. Run these branches and their interrupted counterparts before broad construction. Here **broad construction means beyond the first same-width mutation slice**.

For Windows, the initial forced-flush adapter calls `FlushFileBuffers` on the relevant writable database handle after the required writes. Any auxiliary-file or ordering requirement comes from the native investigation. Do not add a flush at every phase to simplify a model, or claim a successful file flush guarantees more than the declared device/filesystem model.[^flush]

**Nested force and engine options.** Prefer propagating an inner `CommitTrans(dbForceOSFlush)` intent to its parent while keeping the child reversible. TXN-FLUSH-LIVE tests immediate reversible writes, propagated intent and confined/ignored force; paired R-CRASH-1 cases compare survival. Capture effective SetOption/Idle events and option generations. An old registry example does not establish target defaults, and cache refresh is not a demonstrated force barrier.[^options][^idle]

## Native crash baseline and the retired optional idea

**D-UNDO-1 — Decided. K-CRASH:** ACE-, Access- or CalcDb-first reopening must meet ACE's crash-state and commit-survival rules, including `dbForceOSFlush`, without requiring CalcDb recovery first. Reproduce evidenced needs-repair behavior rather than hiding it with automatic repair. A completed healthy write has the separate T-COMPACT-1 goal in I-15; an interrupted ACE-equivalent state need not be healthy.

**D-UNDO-2 — Retired.** Optional undo is an unplanned idea, to reconsider only if real write programs show a useful recovery window. Its codec, state machine, construction slices and R-CRASH-2 are removed from planned work. Live transaction rollback, spill/error handling and crash comparison remain required.

D-UNDO-1's conditional constraints remain unchanged if that idea is reconsidered. A record must identify the same file and cover every physical page in the union of the before/intended extents, including header, maps, catalog, indexes and free pages. It distinguishes uncovered pages from covered before/intended images and records lengths and presence. At recovery, perform a full read under exclusion: **every uncovered page must be unchanged, and every covered page must equal either its complete before-image or its complete intended new image; otherwise discard without applying it.** A torn/third image, changed identity or unrecorded extent is not an accepted alternative. This is the agreed external-change check, not a claim of continuous history or a new USN requirement.[^scope-authority]

No optional mechanism may undo a commit that ACE's ordinary or forced rules require to survive, weaken ACE-first reopening, or supply the baseline writer's safety. These are retained constraints, not a newly scheduled recovery protocol. I-03 and II-08 §24 state the same boundary.

## Crash-parity direction and what implementation settles

R-CRASH-1 preferably records ACE's writes, extent changes and flushes with their contents, including the database, lock file and relevant TEMP activity. Reconstruct candidate interrupted files offline under an explicit observation and storage model. Classify them by independent ACE, Access and Compact & Repair outcomes, and export CalcDb's distinct cut images to the same opener branches. Low-level observation or control tooling, including a kernel driver, may be built for this work without decompiling proprietary binaries.

The goal remains a CalcDb state no worse than ACE's at the corresponding point, with the same commit-survival rules. Exact classification is ambitious and may not be fully achievable. The observation method, attainable coverage, comparison relation, precise pass condition and treatment of unresolved write classes are **settled during implementation**, through R-CRASH-1/CRASH-OBS, CRASH-CONTROL and CRASH-RELATION. This book does not decide that every unknown class ships, or that every such operation is refused.

The dependent tests keep those evidence boundaries. T-TXN-39–42 and T-EVID-28 test model state, trace coverage, interruption capture and independent opening; a successful recorder or exporter is not itself an ACE crash match. Record observed request classes separately from cuts the probe can control. T-TXN-53 and T-EVID-10 use the implemented per-write structure/control list for normally completed output, including a newly created database. Its precise acceptance remains PRD-08 implementation work, independent of the crash relation.

If full capture proves impossible, continue the native writer and its complete CalcDb cut analysis under declared models. Combine available payload traces, externally bracketed native operation/commit observations, smaller fixtures and ordinary opener evidence; retain missing boundaries and contradictory outcomes. Timed process kills do not become exhaustive write-point evidence, and process death does not establish power-loss behavior. The full writer remains scope; a private journal, atomic file replacement or stronger universal atomicity promise does not replace the ACE goal.

## Experiment summaries and implementation checks

**R-TXN-1 — Workspace and local-locker resolution (L).** TXN-LOCAL covers two Workspaces, mixed DAO/ADO, one/two threads, overlapping and disjoint writes, finite retries, visibility and both resolution orders. Existing nesting/statement/close/TEMP/multi-file branches retain mandatory failure work; TXN-FLUSH-LIVE and its timing subcases decide publication timing. Full card: [A-02](A-02-experiments.md).

**R-CRASH-1 — Recorded writes, reconstructed cuts and independent reopeners (L).** CRASH-ORDER-DATA/INDEX and the CRASH-ORDER-REPEAT-REMOVE/ADD subcases discriminate final-image and fallback programs; interruption cases pair with each timing branch. Record capture limits and compare exported ACE/CalcDb images through the same first openers. Precise acceptance is implementation work. Full card: [A-02](A-02-experiments.md).

**R-CRASH-2 — Retired.** Optional-undo work is unplanned. Required exhaustion, uncertain-I/O, live rollback and cleanup failure coverage resides in R-TXN-1 and R-CRASH-1; the ID is not reused.

Measure unique/repeated dirty-page writes, retained/spilled images, transaction metadata, synchronization and actual flushes. The first final-image candidate is compared with fallback costs without claiming either reproduces ACE before the experiments. **The native experiments are specified and unexecuted.**
