## R-ORACLE-1 — Capture, isolation and service recovery

**Size: M.** Create a small known fixture covering all shared scalar tags, exact UTF-16 and byte-counted BSTR payloads, including an odd byte count, plus binary arrays, parameter omission, arrays and object identity, plus a clock/random-value case with declared controllability. Run DAO/Access and ADO as their drivers are available through direct/native/managed callers, recording loaded identities and all result channels; validate encode/decode without lossy JSON/string conversion. Cross worker reuse versus fresh processes, two job IDs versus a repeated ID, the same ID with a different request/fixture digest, transport loss, timeout, an owned dialog and worker death. Reject conflicting job-ID reuse and retain uncertain execution status; do not promise exactly-once mutation across a lost worker. Capture raw artifacts and lifecycle events. Compare repeated captures and a hand-audited baseline; content differences select additional environment dimensions or isolation boundaries, identity/corruption differences require fixing serialization before accepting downstream captures. Prove private-desktop UI handling and safe owned-process cleanup; unresolved automation configurations remain unavailable. Dependencies: user-selected installation and a minimal public-API driver, not a CalcDb implementation. Larger matrices start after this evidence path works.


### T-COMPACT-1 — calibrated “nothing to fix” acceptance, within R-ORACLE-1

**Question and design effect.** Can the harness distinguish a normal compaction from any repair relevant to the operation under test, including a successful or silent repair? This qualifies normal completed outputs of W-05/W-07 and later mutators. It does not require every interrupted ACE-compatible image to be repair-free, and it does not implement CalcDb's later compactor (R-REBUILD-1).

**Conditions.** Use the common recorded environment and exact Access host identity, independently of the reported DAO DLL version. Record the actual command or Automation member invoked, options, file format/sort/encryption, output path, locale, permissions and exclusive admission. The primary lane is the selected Access host's Compact & Repair command. If an Automation method drives it, validate that route against the command on clean and damaged controls; if unavailable, use the owned-process UI driver. Record DAO CompactDatabase as a separate extra lane when used, never as an unlabelled substitution. Do not enable automatic compact-on-close or make changes to macro security as part of a run.

**Fixtures and starting state.** Start from an immutable, native-created fixture covering the operation's row types, indexes, relationships, QueryDefs, properties, long values and opaque front-end objects. Produce C0 by the CalcDb operation and A0 by the matching ACE operation from independent initial copies. Record close/acknowledgement/flush state, file identities, hashes and full bytes before native reopening. Include clean unchanged native controls, clean native controls with comparable allocation/free-space history, and damaged copies whose deliberately injected defect is recorded independently. Damage only disposable copies, one relevant defect class at a time; no proprietary implementation inspection is required.

**Operations.** For each C0/A0/control image, make separate fresh copies for (a) raw preinspection, (b) ACE-first ordinary open, (c) Access-first ordinary open and (d) Compact & Repair first. Each starts with the same frozen bytes and appropriate initial lock-file state; observations or repairs from one branch cannot affect another. The Compact & Repair branch has a fresh run directory/destination, closed source and exclusive access. Capture the method/command outcome and all new files. Reopen its output on fresh copies in ACE and Access, and compact another output copy a second time. Preserve every original source regardless of result.

**Capture.** Keep typed row multisets with multiplicity and exact stored precision, ordering where promised, index logical key/row mappings and required encoded key regions, schema/properties/relationships, SQL and parameter metadata, long-value chains, object identity/reference relationships and protected opaque payload hashes. Capture whole before/after files, allocation and reachability summaries, format validation results, changed-page classification, return/HRESULT/error collections, repair prompts and completion dialogs, logs, and the presence/content of MSysCompactErrors before and after. Capture the diagnostic read order; use separate runs where inspection itself mutates the file. New repair records are identified against the starting fixture, not merely the presence of a table name.

**Comparison.** Establish the normal transformation envelope from clean ACE controls with the same format/options and comparable native history. Allow evidenced relocation, free-page removal and bookkeeping changes; do not mask all index/catalog bytes or demand byte-identical whole files. Compare both C0 and its compacted destination to the expected semantic state, not only to each other, so a pre-existing loss cannot pass by surviving compaction unchanged. Compare key encodings after excluding only independently justified relocation fields. Validate graph ownership before and after, with independent native opens as an additional check; a validator generated from the same format description is useful but is not independent evidence against a shared decoder defect.

**Outcomes and ambiguity.** Pass only if ordinary opens need no repair; no calibrated repair indicator appears; all required content survives; no repair-specific structural correction occurs; all differences fit the clean-control envelope; and the destination reopens with the expected state. Any repair indicator, loss or required correction fails the completed write. Capture gaps, an uncalibrated defect class, inconclusive route equivalence or unexplained changes are inconclusive. A positive damaged control must demonstrate the sensitivity needed for that class. If Access silently rebuilds both healthy and damaged structures in an indistinguishable way, no conclusion about absence of internal repair follows from that class until preimage validation/controls can discriminate it. Repeated compaction tests stability, not canonical byte identity. Build differences remain separate lanes.

**Dependencies and size.** Part of R-ORACLE-1 (M), using R-FMT-1 for initial structural inspection and the relevant R-FMT-2/R-SORT-3/R-CAT-1/R-PRESERVE-1 evidence as each mutation class arrives. Start clean/positive-control calibration before W-05; operation-specific coverage grows with its writer. No dependency on W-L4 or a completed CalcDb compactor.

**Source boundary.** S-MS-REPAIR-GUIDE documents ordinary compaction, possible data loss and partial-repair indicators; S-MS-COMPACT documents a separate DAO operation. The calibration, independent branches and acceptance rule above are proposed CalcDb test design. Neither source states that a successful return or an absent error table proves no repair happened.

## R-STRING-1 — DAO value materialization, reuse and ownership

**Question and provisional choice.** Does direct construction of the final owned BSTR outperform reusable UTF-16 scratch or a bounded decoded-field cache for the priority DAO row loop, once decode work, output copies, retained capacity and pins are all counted? Provisionally use direct construction for one read and bounded scratch for demonstrated reuse. The common representation is the real platform Automation VARIANT and BSTR; Windows x64 uses 24-byte VARIANTs. Current CalcVBA's 16-byte value is being corrected and is not the target design.

**Fixtures and operations.** Use rows containing required scalars, Null, empty strings, embedded U+0000, isolated surrogate units, short and long text, mixed native compression, and Memo values spanning the evidenced storage forms. Read once and repeatedly, by ordinal and name; alternate fields; vary projected-column count; move across pages, revisit rows and cross cache budgets. Exercise edits, Requery and schema-generation changes. Retain returned values across movement and Close; copy and clear them through the matching Automation service. Include large-value sizing and allocation failure, malformed lengths/chains and invalidated decode scratch. Add inbound binary BSTRs with odd byte counts: preserve exact byte length/payload in capture and copy, and test text coercion/rejection separately. Exercise legal ByRef input snapshots and actual writeback contracts separately.

**Boundary extensions.** Include Decimal with nonzero high word, sign and scale, SAFEARRAYs with nonzero bounds and mixed owned elements, object-valued results, locked-array cleanup and partial construction. These are ABI/ownership probes and need not all be native row storage types. A scalar-only round trip cannot validate the 24-byte stride, Decimal overlay, array lifetime or object retention. Actual CalcVBA native/portable callers and both Windows .NET families require separate observations; a mock implementation is labelled as such.

**Capture and comparison.** First compare active VARIANT tags, exact values, exact BSTR byte lengths/payloads and UTF-16 units for text, array bounds/element order, error outputs and lifetime behavior. Ignore inactive/padding bytes in semantic equality while retaining separate ABI-layout captures. Instrument allocations/frees by owner/service, live and peak capacity, emitted UTF-16 units, copied payload bytes, page pins and their duration, name probes/cache invalidations and actual COM crossings. Separate cold initialization, resident-row work and page acquisition. Retain A/A timing controls, allocation failures and external-free visibility limits. Reentrant callback cases share R-UDF-1 and must not expose scratch after invalidation or repeat a host effect.

**Outcomes.** Any semantic, error or ownership mismatch rejects the candidate irrespective of speed. A scratch path that saves decode work but retains excessive capacity/pins selects a smaller retention policy; single-read and repeated-expression workloads may legitimately choose different paths. No measured advantage keeps the simpler direct construction. Unstable timing or unexplained allocation requires a reduced repeat. Failure under a valid large-value request changes admission/reporting or implementation, never silently truncates the result.

**Dependencies, effort and next action.** R-ORACLE-1 capture and I-FOUNDATION-1's smallest canonical ABI/ownership fixture; no complete DAO, SQL or writer prerequisite. Size **M**. Begin with one resident row, scalar/text reads and a retained BSTR; then add native compression/long-value cases as R-FMT-1/2 supplies descriptors. Decides **D-STRING-1** and informs D-PERF-1; owning chapters I-02 and II-02.

## R-CRASH-1 — Write-point crashes, surviving commits and independent reopeners

**Question and decision.** For each principal mutation, which database, lock-file and recovery states can ACE leave when interrupted at every write boundary, and which commits survive ordinary commit versus `dbForceOSFlush`? This evidence constrains D-WRITE-1 and D-UNDO-1: the writer's ordering, acknowledgement, flush and repair-marking protocol. Private recovery cannot establish the ACE-first guarantee.

**Dependencies and size.** R-TXN-1 supplies transaction semantics; W-PROBE supplies an independent native observation/failure harness, before W-05 exists; complete ACE tracing is an attempted later increment of that probe, not a prerequisite for its native open/read/lock basics. R-FMT-1/2, minimal R-CAT-1 native catalog probes and preservation evidence supply meaningful comparisons for the corresponding fixture. R-CAT-1 does not require completed catalog writing. R-LOCK-1 establishes the CalcDb exclusive lease before qualified writer replay. Initial scope **L**, with storage/environment extensions separately estimated. Replay the accepted matrix against CalcDb after W-05; do not make the initial ACE evidence depend on the production CalcDb pager.

**Fixture matrix.** Start each run from a fresh immutable fixture with known rows, long values, indexes, allocation state and catalog objects. Exercise scalar row changes; variable-row growth/shrink and relocation; inserts/deletes; inline/overflow long-value creation, growth, replacement and deletion; indexed-key updates, duplicate keys and index splits/merges/root changes; AutoNumber allocation; allocation reuse, map-capacity transitions and file growth; table/index DDL, catalog/property mutations and saved QueryDef create/change/delete. Include implicit operations, explicit commit/rollback, nested transactions and Workspace transactions spanning multiple databases. Record the exact operation sequence, parameters, options, transaction depth, affected files and caller-visible acknowledgements. ## R-CRASH-2 — Exhaustion, uncertain completion and guarded optional undo

**Question and decision.** What does ACE expose when TEMP space, database growth, transaction bookkeeping or I/O fails, and can CalcDb preserve that behavior while offering optional CalcDb-first undo? An interrupted or failed request can have persistent effects: classify uncertain outcomes instead of assuming cancellation/error means no write. Reopen the same fixture without any optional undo to establish native behavior independently.

**Optional-undo record and full-read predicate.** Seal the record before covered database writes, retaining identity/incarnation, operation and rollback eligibility, record integrity, before/intended lengths and a manifest for the union of the before/intended page extents. It partitions every page into covered C or uncovered U, including headers, maps, indexes and catalog with no unchecked ranges. U carries baseline fingerprints; C carries before-images and intended new images or their fingerprints, each with length and ABSENT alternatives for creation/removal. Under exclusion at recovery, verify file identity and record integrity, then read the entire file. Every U page must be unchanged and every C page must equal its before-image or intended new image; otherwise discard before making a recovery write. Length, presence and any partial final-page length must agree with a recorded before/intended alternative. Reject unrecorded extents, intermediate lengths and torn/third images. Allow mixtures of whole before/new pages. The exact shared definition is in I-03/I-08.

The predicate is the user's selected external-change check, without a continuous-history/USN requirement. Equal current bytes are not proof that no past modification happened. A changed-and-restored history that meets the identity, image, length and rollback-eligibility checks is not rejected merely because such history is possible; this choice is recorded, not strengthened into a new approval condition.

**Eligibility matrix.** Test all-before, all-intended and mixed complete-page states; changed uncovered header/catalog/map pages; covered before, intended and third/torn images; new pages absent/present, expected truncation and recorded partial-tail cases; unexpected growth/truncation/intermediate length; same-path replacement, identity reuse ambiguity, stale/missing/truncated/corrupt records and competing openers. Use identity-preserving snapshots where necessary; ordinary file copies with new identities must not accidentally qualify. For rejected records verify zero recovery writes to the database. If identity cannot be supported by the backend, optional undo stays disabled; that does not replace the native crash baseline.

**Disarm, recovery and disposal.** An all-intended image alone cannot distinguish an eligible interrupted operation from a commit that the native baseline requires to survive, including a commit whose success never reached the caller. Identify the earliest evidenced commit-survival frontier for each operation and declared fault model, then test a durable rollback-eligibility disarm before crossing it. Interrupt before/after record sealing, disarm submission/completion, the native survival frontier, logical commit, ordinary/forced acknowledgement, recovery writes and disposal; explicitly include the interval after native survival is established but before the API returns. Force failures/exhaustion at each point and verify the retained primary/secondary errors and subsequent admissible calls. No surviving sidecar may undo a commit required to survive merely because it was unacknowledged. Disarm must preserve ACE's native ordinary and forced survival classes; it must not make an ordinary database commit durable solely to rescue the sidecar design. If the frontier or the required ordering cannot be demonstrated for an operation/backend, disable the optional enhancement there.

**Outcomes and next step.** Every interrupted recovery-write state must independently satisfy ACE-first safety, even when the sidecar is removed or rejected next time. Compare eligible CalcDb-first enhancement with the identical crash state lacking undo, while accepting the independent ACE/Access branches against their baseline. A failed image/identity/eligibility check discards the record; a failed native parity comparison changes the writer/rollback protocol; inconclusive native coverage stays labelled. Start with one fixed-page update manifest and an adversarial uncovered-header change, then add allocation/length and disarm cases. The user reports that current CalcVBA internally uses its own 16-byte form and converts at COM boundaries; the target is the exact platform VARIANT, including 24 bytes on Windows x64. This investigation selects package/services, not another semantic representation.

**Declaration discovery.** Begin immediately with supplied integration material, available public/shared declarations and dependency manifests. Publish the actual ABI, owner/caller responsibilities, supported tags and allocator pairs; do not invent existing CalcVBA function names or JIT/runtime layouts. Compare the actual Windows SDK declaration against shared C/Rust declarations: size, alignment, tag/payload/Decimal offsets, record pointer-pair capacity, calling convention and array stride. Record compiler/SDK/runtime identities and any packing options. A compile-only assertion is distinct from an actual caller round trip.

**Concrete portable requirements.** Inventory IUnknown identity/refcounts; IClassFactory activation/LockServer/aggregation conditions; real vtables; IDispatch GetTypeInfoCount/GetTypeInfo/GetIDsOfNames/Invoke; the ITypeInfo/type-library query and descriptor-release surface consumed by early binding; HRESULT, argument errors, IErrorInfo/EXCEPINFO and set/get error state; IEnumVARIANT Next/Skip/Reset/Clone; IConnectionPointContainer/IConnectionPoint and necessary connection enumerators for ADO events; task-memory pairs where required; BSTR allocation/length/free; VARIANT init/copy/indirect-copy/clear; SAFEARRAY creation/copy/destruction/bounds/elements/access. The I-13 table defines the acceptance obligations. No apartment, cross-thread or process marshaling service is added.

**Executable fixtures.** After the corrected implementation/prototype exists, run both directions through C++/Rust and each real managed Windows client, plus actual CalcVBA early/late-bound callers. On native non-Windows and wasm32 use the actual CalcVBA client with its CalcVBA-owned stand-in; a Rust-only client/server pair is preliminary local evidence. Cover Empty/Null/missing/error forms; integer widths and floating types; Decimal's sign/scale/high word; Currency/Date; BSTR embedded nulls/surrogates; SAFEARRAY dimensions/nonzero bounds/variant stride/object elements; legal ByRef forms with snapshots and writeback; object/record cleanup as required by the supported surface. Add partial allocation failure, nested calls, locked-array clear and moved-from destruction. Include odd-length binary BSTR allocation/length/copy using the real byte-length services, keeping its raw ownership contract distinct from text coercion.

**Copy admission and concurrency.** Native VariantCopy/VariantCopyInd offer no incremental allocation-budget callback: test conservative preflight/reservation for supported stable ownership graphs, or an explicitly budget-aware shared-foundation copy. Record opaque record/foreign allocations separately and reject an unbounded opaque copy when a hard limit is required. VariantCopy is documented as not thread-safe; default native copy/cleanup and foreign reference operations to the caller thread, then validate the actual multi-caller/concurrency/reentry policy. A caller-thread default is not proof of simultaneous-call safety, and no internal latch or global mutex spans foreign AddRef/Release/record callbacks. No hidden runtime or worker dispatch substitutes for that evidence.

**Portable interface fixtures.** Resolve names and types for real early binding; enumerate a collection with partial Next and cloned position; consume thread error info once and exercise nested failure; Advise an ADO event sink, reject a wrong outgoing IID, invoke on the caller thread, Unadvise during callback and close reentrantly. Capture exact IIDs/DISPIDs from permitted metadata rather than writing guessed constants. Track subscriptions, object references, array locks and allocator ownership through shutdown.

**Capture and outcomes.** Preserve declarations/builds, active value fields, exact BSTR byte lengths/payloads and text units, array shape, allocation and reference logs, call threads, error state and module provenance. ABI mismatch requires correction of the shared declaration/runtime; missing precision or service requires a shared foundation extension. Incomplete declarations or unavailable target execution remain unresolved; no private CalcDb coercion or object protocol closes the case. An unavoidable dependency cycle changes package placement under **D-VALUE-1 — Decided representation; provisional package**. The 24-byte Windows x64 representation itself is decided.

**Dependencies, effort and next action.** Discovery depends only on supplied/available material, not a completed portable prototype. Execution depends on the corrected CalcVBA shared value implementation and its own minimal portable services. Size **S** for contract investigation; estimate implementation separately after inventory. Next action: publish declarations and demonstrate one allocation/value/dispatch round trip, then early-binding/enumeration/error/event paths. Owning chapters I-02, I-13 and II-02.

## I-HOST-1 — activation, callbacks and shutdown ownership

**Question and provisional choice.** Can a small explicit versioned capability boundary assign host loading, runtime initialization, type-library resolution, activation scope, VFS/configuration, function invocation and diagnostics without introducing another database API? Prefer that boundary under **D-HOST-1 — Provisional**. Database operations remain real COM calls into the shared engine.

**Fixture and operations.** Use the actual host loading prototype and the declarations from I-FOUNDATION-1. Negotiate version/capabilities; create an object; inject one configuration/effect service; call one function with owned canonical arguments and result; return one public error. Reenter to move or close the outer recordset/database, alter a retained dependency or unsubscribe an event sink. Include callback exceptions, nested activation scopes, missing services, version mismatch, failed allocation and shutdown while factories, objects, subscriptions or calls survive. Preserve caller-thread execution and blocking public calls; the portable stand-in supplies no marshaling shortcut.

**Capture.** Record caller/execution threads, active scope owners and nesting, arguments/result owners, internal latch state, logical-lock policy, callback count, generation checks, error publication and eventual resource release. Distinguish owned memory remaining live from an object whose operation state is closed. Capture foreign Release/destruction during teardown so cleanup reentry is not hidden from the lifetime analysis.

**Outcomes.** Select the smallest explicit contract that represents the observed host requirements. A missing activation or runtime service extends host/foundation work; it does not create a CalcDb-only object protocol. A callback on the wrong thread, exposed scratch, repeated effect or continuation after invalidation rejects the candidate. Missing capability/version produces a named integration failure. Separate host-version conflicts and incomplete traces from accepted behavior; R-UDF-1 resolves function semantics and R-ADO-1 event ordering.

**Dependencies, effort and next action.** I-FOUNDATION-1 declaration discovery and minimal host loading; no full SQL/DAO prerequisite. Size **M**. Begin with real host creation, one owned value call and one reentrant callback, then lifetime-aware shutdown. Owning chapter I-13.
