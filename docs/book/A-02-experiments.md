## R-ORACLE-1 — Capture, isolation and service recovery

**Size: M.** Create a small known fixture covering all shared scalar tags, exact UTF-16 and byte-counted BSTR payloads, including an odd byte count, plus binary arrays, parameter omission, arrays and object identity, plus a clock/random-value case with declared controllability. Run DAO/Access and ADO as their drivers are available through direct/native/managed callers, recording loaded identities and all result channels; validate encode/decode without lossy JSON/string conversion. Cross worker reuse versus fresh processes, two job IDs versus a repeated ID, the same ID with a different request/fixture digest, transport loss, timeout, an owned dialog and worker death. Reject conflicting job-ID reuse and retain uncertain execution status; do not promise exactly-once mutation across a lost worker. Capture raw artifacts and lifecycle events. Compare repeated captures and a hand-audited baseline; content differences select additional environment dimensions or isolation boundaries, identity/corruption differences require fixing serialization before accepting downstream captures. Prove private-desktop UI handling and safe owned-process cleanup; unresolved automation configurations remain unavailable. Dependencies: user-selected installation and a minimal public-API driver, not a CalcDb implementation. Larger matrices start after this evidence path works.


### T-COMPACT-1 — calibrated “nothing to fix” acceptance, within R-ORACLE-1

**Question and design effect.** Can the harness distinguish a normal compaction from any repair relevant to the operation under test, including a successful or silent repair? This qualifies normal completed outputs of W-05/W-07 and later mutators. It does not require every interrupted ACE-compatible image to be repair-free, and it does not implement CalcDb's later compactor (R-REBUILD-1).

**Conditions.** Use the common recorded environment and exact Access host identity, independently of the reported DAO DLL version. Record the actual command or Automation member invoked, options, file format/sort/encryption, output path, locale, permissions and exclusive admission. The primary lane is the selected Access host's Compact & Repair command. If an Automation method drives it, validate that route against the command on clean and damaged controls; if unavailable, use the owned-process UI driver. Record DAO CompactDatabase as a separate extra lane when used, never as an unlabelled substitution. Do not enable automatic compact-on-close or make changes to macro security as part of a run.

**Fixtures and starting state.** Start from an immutable, native-created fixture covering the operation's row types, indexes, relationships, QueryDefs, properties, long values and opaque front-end objects. Produce C0 by the CalcDb operation and A0 by the matching ACE operation from independent initial copies. Record close/acknowledgement/flush state, file identities, hashes and full bytes before native reopening. Include clean unchanged native controls, clean native controls with comparable allocation/free-space history, and damaged copies whose deliberately injected defect is recorded independently. Damage only disposable copies, one relevant defect class at a time; no proprietary implementation inspection is required.

**Operations.** For each C0/A0/control image, make separate fresh copies for (a) raw preinspection, (b) ACE-first ordinary open, (c) Access-first ordinary open and (d) Compact & Repair first. Each starts with the same frozen bytes and appropriate initial lock-file state; observations or repairs from one branch cannot affect another. The Compact & Repair branch has a fresh run directory/destination, closed source and exclusive access. Capture the method/command outcome and all new files. Reopen its output on fresh copies in ACE and Access, and compact another output copy a second time. Preserve every original source regardless of result.

**Capture.** Keep typed row multisets with multiplicity and exact stored precision, ordering where promised, index logical key/row mappings and required encoded key regions, schema/properties/relationships, SQL and parameter metadata, long-value chains, object identity/reference relationships and protected opaque payload hashes. Capture whole before/after files, allocation and reachability summaries, format validation results, changed-page classification, return/HRESULT/error collections, repair prompts and completion dialogs, logs, and the presence/content of MSysCompactErrors before and after. Capture the diagnostic read order; use separate runs where inspection itself mutates the file. New repair records are identified against the starting fixture, not merely the presence of a table name.

**Comparison.** Establish the normal transformation envelope from clean ACE controls with the same format/options and comparable native history. Allow evidenced relocation, free-page removal and bookkeeping changes; do not mask all index/catalog bytes or demand byte-identical whole files. Compare both C0 and its compacted destination to the expected semantic state, not only to each other, so a pre-existing loss cannot pass by surviving compaction unchanged. Compare key encodings after excluding only independently justified relocation fields. Validate graph ownership before and after, with independent native opens as an additional check; a validator generated from the same format description is useful but is not independent evidence against a shared decoder defect.

**Outcomes and ambiguity.** Pass only if ordinary opens need no repair; no calibrated repair indicator appears; all required content survives; no repair-specific structural correction occurs; all differences fit the clean-control envelope; and the destination reopens with the expected state. Any repair indicator, loss or required correction fails the completed write. Capture gaps, an uncalibrated defect class, inconclusive route equivalence or unexplained changes are inconclusive. A positive damaged control must demonstrate the sensitivity needed for that class. If Access silently rebuilds both healthy and damaged structures in an indistinguishable way, no conclusion about absence of internal repair follows from that class until preimage validation/controls can discriminate it. Repeated compaction tests stability, not canonical byte identity. Build differences remain separate lanes.

**Dependencies and size.** Part of R-ORACLE-1 (M), using R-FMT-1 for initial structural inspection and the relevant R-FMT-2/R-SORT-3/R-CAT-1/R-PRESERVE-1 evidence as each mutation class arrives. Start clean/positive-control calibration before W-05; operation-specific coverage grows with its writer. No dependency on W-L4 or a completed CalcDb compactor.

**Source boundary.** S-MS-REPAIR-GUIDE documents ordinary compaction, possible data loss and partial-repair indicators; S-MS-COMPACT documents a separate DAO operation. The calibration, independent branches and acceptance rule above are proposed CalcDb test design. Neither source states that a successful return or an absent error table proves no repair happened.

## R-STRING-1 — DAO value materialization, reuse and ownership

**Question and provisional choice.** Does direct construction of the final owned BSTR outperform reusable UTF-16 scratch or a bounded decoded-field cache for the priority DAO row loop, once decode work, output copies, retained capacity and pins are all counted? Provisionally use direct construction for one read and bounded scratch for demonstrated reuse. The common representation is the real platform Automation VARIANT and BSTR; Windows x64 uses 24-byte VARIANTs. Current CalcVBA's 16-byte value is being corrected and is not the target design.

**Fixtures and operations.** Use rows containing required scalars, Null, empty strings, embedded U+0000, isolated surrogate units, short and long text, mixed native compression, and Memo values spanning the evidenced storage forms. Read once and repeatedly, by ordinal and name; alternate fields; vary projected-column count; move across pages, revisit rows and cross cache budgets. Exercise edits, Requery and schema-generation changes. Retain returned values across movement and Close; copy and clear them through the matching Automation service. Include large-value sizing and allocation failure, malformed lengths/chains and invalidated decode scratch. Add inbound binary BSTRs with odd byte counts: preserve exact byte length/payload in capture and copy, and test text coercion/rejection separately. Exercise legal ByRef input snapshots and actual writeback contracts separately.

**Boundary extensions.** Include Decimal with nonzero high word, sign and scale, SAFEARRAYs with nonzero bounds and mixed owned elements, object-valued results, locked-array cleanup and partial construction. These are ABI/ownership probes and need not all be native row storage types. A scalar-only round trip cannot validate the 24-byte stride, Decimal overlay, array lifetime or object retention. Actual CalcVBA native/portable callers and both Windows .NET families require separate observations; a mock implementation is labelled as such.

**Capture and comparison.** First compare active VARIANT tags, exact values, exact BSTR byte lengths/payloads and UTF-16 units for text, array bounds/element order, error outputs and lifetime behavior. Ignore inactive/padding bytes in semantic equality while retaining separate ABI-layout captures. Instrument allocations/frees by owner/service, live and peak capacity, emitted UTF-16 units, copied payload bytes, page pins and their duration, name probes/cache invalidations and actual COM crossings. Separate cold initialization, resident-row work and page acquisition. Retain A/A timing controls, allocation failures and external-free visibility limits. Reentrant callback cases share R-UDF-1 and must not expose scratch after invalidation or repeat a host effect.

**Outcomes.** Any semantic, error or ownership mismatch rejects the candidate irrespective of speed. A scratch path that saves decode work but retains excessive capacity/pins selects a smaller retention policy; single-read and repeated-expression workloads may legitimately choose different paths. No measured advantage keeps the simpler direct construction. Unstable timing or unexplained allocation requires a reduced repeat. Failure under a valid large-value request changes admission/reporting or implementation, never silently truncates the result.

**Dependencies, effort and next action.** R-ORACLE-1 capture and I-FOUNDATION-1's smallest canonical ABI/ownership fixture; no complete DAO, SQL or writer prerequisite. Size **M**. Begin with one resident row, scalar/text reads and a retained BSTR; then add native compression/long-value cases as R-FMT-1/2 supplies descriptors. Decides **D-STRING-1** and informs D-PERF-1; owning chapters I-02 and II-02.

## R-FMT-1 — Format families, descriptors and minimal valid files

**Question and conditions.** Which file-visible signatures and feature combinations select each supported Jet 4/ACE descriptor, and which ranges remain unexplained? Use I-15's verified engine/host and file-format conditions, retaining file metadata, creation options and the exact public creation route. Keep executable build identity distinct from native format identifiers; an executable version is not itself a substitute for a file descriptor.

**Fixtures and operations.** Create the smallest practical native files through ACE/Access, then vary one evidenced format option or feature at a time. Add a table, individual scalar field families, a primary/nonprimary index, properties and a saved query in separate fixtures. Include empty and populated tables, renamed/deleted columns, different visible versus physical column orders, and supported legacy/current sort settings. Preserve the creator's complete original file; “minimal” does not mean deleting unexplained bytes until another reader happens to accept it. Open read-only where permitted, enumerate public metadata and values, close, and reopen each fixture through ACE and Access. Extend with discriminating combinations when single-feature changes do not identify a layout rule.

**II-03 concrete probe set.** Check the complete version-field bytes, 4096-byte geometry, page-0 raw/decoded mask domain, broad page kinds, kind-01 ordinary/map-declaration/LVAL subtypes, and page-1 row-0 global-map location against independently created files. Treat II-03's constructed byte examples as hypotheses to compare, not as oracle fixtures already accepted.

**II-04 structural discrimination.** Confirm the25-byte column blocks, physical number/variable index/distinct column ID, historical versus active counts, type-dependent metadata and ordinary/calculated dispatch. Force TableDef continuations and record the exact logical-to-physical segment mapping. Use independently created files with Large Number and Date/Time Extended, plus calculated Boolean/Numeric/Text/Memo where admitted; source profile names or an Office16 executable alone do not establish the file-visible variant. Bootstrap ResultType/property metadata only for the calculated branches; ordinary row decoding does not require a complete expression engine.

**Capture and comparison.** Record before/after files and lock state even for opens, public schema/type/property views, typed rows and errors. Classify changed pages and candidate headers, directories, roots, type descriptors, references and unknown spans. Cross-check the proposed descriptor against independently generated fixtures and public observations; agreement among generated CalcDb reader, writer and validator is not independent evidence. Any malformed-fixture extension stays separate from valid-format inference and records both safe parser behavior and the oracle's acceptance/error.

**Outcomes, dependencies and next step.** Stable file-visible distinctions select explicit descriptor fields or variants. Unexplained bytes remain attached to their owning structures; unknown signatures or contradictory layouts prevent claiming support and prohibit speculative writes. A build-dependent result gets separate captures and an explicit compatibility decision rather than a hidden executable-version switch. R-FMT-1 decides D-FMT-1's concrete descriptor boundaries; R-FMT-2 supplies mutation details. Dependency: R-ORACLE-1; size **L**. Start with the empty-file/table/scalar fixture family and a byte inspector, without waiting for the production writer.

## R-FMT-2 — Rows, long values, allocation and native mutations

**Question and conditions.** Which physical row, long-value, ownership and allocation rules permit interoperable mutations for each R-FMT-1 descriptor? Apply I-15's common conditions and vary operation and transaction options explicitly. This is ordinary mutation evidence; write interruption, commit survival and repair marking are separately tested by R-CRASH-1/2 in I-08.

**Fixtures and operations.** Grow tables through page/slot and allocation-map boundaries. Insert, update and delete fixed/variable fields; cross row-growth, relocation, fragmentation and reuse boundaries; alter indexed values and rows with deleted or reordered columns. Vary Null, Boolean, empty text, compressed/uncompressed segments, embedded zero units and surrogate units. Exercise all initial scalar representations, including Decimal precision/scale, GUID/AutoNumber behavior and extended date/time payload/precision; retain native bytes and public projections separately. Test inline, single-external and chained long values around observed form transitions, then grow, shrink, replace, delete and reuse their space. Include multiple objects with different ownership maps, inline/reference map transitions, file growth and index splits/root changes. Repeat with explicit commit/rollback and failed unique/default/validation operations where applicable; R-TXN-1 determines logical outcome scope.

**II-03 concrete mutation probes.** Check 14-byte data headers, two-byte slot flags/offsets, the 255-slot boundary, row-plus-three-byte-page locators, packed insertion versus fragmented placement, shared map-declaration pages and inline/reference bitmap transitions. ## R-PRESERVE-1 — Opaque objects, protected bytes and shared references

**Question and conditions.** Can ordinary CalcDb edits preserve every untouched object and unknown property together with its required location/reference relationships? Apply I-15's common conditions to files containing both supported user tables and Access front-end objects, plus unknown properties and later-capability metadata/payloads where the selected format permits them. Presence in the corpus does not authorize executing stored modules/macros or implementing deferred capabilities early.

**Fixtures and operations.** Obtain immutable ACE/Access-created baselines with forms, reports, macros, modules, native QueryDefs and properties. Add discriminating opaque payloads, shared references and allocation adjacency as their native ownership is established. Make isolated row edits, long-value growth/shrinkage, index changes and supported catalog/property mutations, then combined operations that force allocation pressure or relocation. Exercise rollback and failed preflight. Include no-op open/read/close to distinguish opener bookkeeping from unintended rewriting. Keep any compacted baseline and each diagnostic repair result as separate derivatives.

**II-04 preservation cases.** Retain deleted-column fixed bytes, unused variable positions, padding, noncanonical-but-native-accepted scalar/text encodings, calculated prefix/trailer bytes, LV-definition opaque words and declaration tails. Force row relocation beside an anchored opaque block and retirement of one long value among packed neighbors. Verify raw-preserving edits do not round dates/Decimals or rebuild OLE payloads through public values; a required unknown reference prevents publication rather than being dropped.

**Capture and comparison.** Mark understood changed ranges and protected ranges before each proposed mutation. Compare protected bytes exactly and verify their containing identity, incoming/outgoing references, ownership and reachability; a byte-for-byte copy at an unverified new location is insufficient. Capture ACE/Access metadata and supported raw/readback views before and after, normal-open results, ordinary table/query behavior and a separate Compact & Repair diagnostic. For CalcDb's refused path, verify that preflight made no database mutation. Record unexplained differences rather than masking them as generic catalog noise.

**Outcomes, dependencies and next step.** Exact protected bytes plus established references and successful interoperability expand the permitted mutation set for D-OPAQUE-1. Unknown relocation or sharing keeps the affected write refused and counted as a failed/missing compatibility case; opaque data must not be dropped to make a writer pass. A changed range with no explanation selects a smaller fixture and explicit preservation rule. Dependencies: R-FMT-1/2; size **M**. Start with a supported table edit beside one preserved front-end object and one unknown property, then extend to structural/allocation changes. Crash-state preservation follows I-08's ACE baseline, not an invented all-bytes-unchanged crash promise.

## R-CRASH-2 — Exhaustion, uncertain completion and guarded optional undo

**Question and decision.** What does ACE expose when TEMP space, database growth, transaction bookkeeping or I/O fails, and can CalcDb preserve that behavior while offering optional CalcDb-first undo? This decides D-TXN-1 resource/error handling and D-UNDO-1 eligibility, disarming and disposal. **Dependencies / size:** R-TXN-1, R-CRASH-1's harness/fault taxonomy, R-LOCK-1 exclusion and native identity evidence; **M** as additional cases reusing the harness. **Cases and measurements.** At each applicable reservation, spill, extension, overwrite and commit/rollback milestone, inject exhaustion, short/failed writes and flush failures; separately interrupt before and after the failure/error acknowledgement. An interrupted or failed request can have persistent effects: classify uncertain outcomes instead of assuming cancellation/error means no write. **Optional-undo record and full-read predicate.** Seal the record before covered database writes, retaining identity/incarnation, operation and rollback eligibility, record integrity, before/intended lengths and a manifest for the union of the before/intended page extents. It partitions every page into covered C or uncovered U, including headers, maps, indexes and catalog with no unchecked ranges. U carries baseline fingerprints; C carries before-images and intended new images or their fingerprints, each with length and ABSENT alternatives for creation/removal. Under exclusion at recovery, verify file identity and record integrity, then read the entire file. Every U page must be unchanged and every C page must equal its before-image or intended new image; otherwise discard before making a recovery write. Length, presence and any partial final-page length must agree with a recorded before/intended alternative. Reject unrecorded extents, intermediate lengths and torn/third images. Allow mixtures of whole before/new pages. The exact shared definition is in I-03/I-08.

The predicate is the user's selected external-change check, without a continuous-history/USN requirement. Equal current bytes are not proof that no past modification happened. A changed-and-restored history that meets the identity, image, length and rollback-eligibility checks is not rejected merely because such history is possible; this choice is recorded, not strengthened into a new approval condition.

**Eligibility matrix.** Test all-before, all-intended and mixed complete-page states; changed uncovered header/catalog/map pages; covered before, intended and third/torn images; new pages absent/present, expected truncation and recorded partial-tail cases; unexpected growth/truncation/intermediate length; same-path replacement, identity reuse ambiguity, stale/missing/truncated/corrupt records and competing openers. Use identity-preserving snapshots where necessary; ordinary file copies with new identities must not accidentally qualify. For rejected records verify zero recovery writes to the database. If identity cannot be supported by the backend, optional undo stays disabled; that does not replace the native crash baseline.

**Disarm, recovery and disposal.** An all-intended image alone cannot distinguish an eligible interrupted operation from a commit that the native baseline requires to survive, including a commit whose success never reached the caller. Identify the earliest evidenced commit-survival frontier for each operation and declared fault model, then test a durable rollback-eligibility disarm before crossing it. Interrupt before/after record sealing, disarm submission/completion, the native survival frontier, logical commit, ordinary/forced acknowledgement, recovery writes and disposal; explicitly include the interval after native survival is established but before the API returns. Force failures/exhaustion at each point and verify the retained primary/secondary errors and subsequent admissible calls. No surviving sidecar may undo a commit required to survive merely because it was unacknowledged. Disarm must preserve ACE's native ordinary and forced survival classes; it must not make an ordinary database commit durable solely to rescue the sidecar design. If the frontier or the required ordering cannot be demonstrated for an operation/backend, disable the optional enhancement there.

### II-08 receipt and optional-recovery branches

**FAIL-OWNER — every exit retains its effects.** Inject failures while claiming the resolution slot, reserving merge/publication/deferred-release storage, preparing optional metadata, submitting/settling writes, flushing, publishing views and constructing/marshalling the public outcome. **UNDO-CODEC — bounded private record.** Exercise the proposed v1 header, exact 96-byte manifest entries, before blobs and Armed/Disarmed frames with invalid counts, role/presence flags, overflows, duplicate/missing pages, overlapping/out-of-body blobs, unknown identity/profile, bad digest, extra or truncated tail and control-generation/nonce disagreement. **UNDO-AUDIT — exact selected predicate.** Use the 81→82-page witness with C={1,17,40,44,80,81}, including existing-free page80's real prior bytes and truly absent page81. Test complete before/intended mixtures, changed U header/catalog/map/free pages, covered third or torn images, full/partial tails and all length alternatives. No page may be restored before the complete current file passes. No USN/history predicate is added.

**UNDO-LIFETIME — failed setup and stale eligibility.** Force a seal or seal-flush failure that nevertheless leaves a readable Armed record, then attempt another native mutation. The possible record retains a retirement obligation; dropping an in-memory pointer or disabling the option cannot erase it. Repeat with failed retirement, missing/unreadable nonce and duplicate/older candidates. Use the retained candidate handle/discovery identity where parsing cannot supply a trusted nonce. Never resurrect an older candidate to make recovery succeed.

**UNDO-FRONTIER — disarm before the crossing submission.** Determine the first effect whose submission can cross the earliest native survival frontier under any allowed persistence schedule, including spontaneous persistence of already buffered writes. Interrupt before/after sidecar disarm write and qualified completion, native submission, native survival and caller return. Unknown frontier or unsupported ordering disables this optional profile before arming. Sidecar durability must not add a database/volume flush or change ordinary versus forced native survival.

**UNDO-ONESHOT — preferred D-UNDO-2 protocol.** Audit the full current file, compile an admitted recovery program, retain its before data/receipts, then durably disarm before its first database write. Interrupt after disarm and at every restoration write/flush/extent cut. Each resulting native state must satisfy ACE-first parity with the record absent or inactive; the next CalcDb opener does not replay it. This intentionally sacrifices a repeat recovery opportunity. A later replayable protocol needs separate evidence, not an extra accepted page-image alternative.

**UNDO-SCOPE — restoration limits.** Begin with qualified single-file fixed-extent operations. Native generated-counter or other surviving effects that complete-before restoration would erase disable that optional profile; do not redefine the before-image. Add ExistingFree, append and truncation independently. Multi-file enhancement remains disabled until every relevant participant can be excluded/audited before writes and its native partial/final survival preserved. Several sidecars do not create durable distributed atomicity.

**Outcomes and size.** Retain the existing exact full-file predicate and native baseline. Receipt/cleanup bugs change implementation; native outcome differences change the selected operation policy; insufficient identity/frontier/recovery-cut evidence leaves the optional profile disabled. This remains M as a fault-case extension of the shared R-CRASH-1 harness; codec/predicate checks and native durability observations are reported separately.


**Final resolution-path discriminators.** Once an audit has found a definite mismatch, a later read/resource failure remains Reject with a secondary error and zero recovery writes. Reject and no-admitted-recovery-program branches retain any failed/uncertain retirement obligation. Distinguish a live uncertain disarm or visible damaged tail from a fresh opener finding exact original Armed bytes when an unconfirmed disarm persisted nothing and the protected frontier remained uncrossed. Empty commits and logical-first programs retain executed logical nodes after later error; a qualified HandedOff result transfers the same continuation without requiring the original suffix to finish or resolving twice.

### II-10 metadata, entry ownership and revocation

Retain the full I-HOST-1 activation/version/callback/shutdown card and its II-09 owned Windows wait branch.

**Metadata and ABI slice.** Use actual CalcVBA and I-FOUNDATION-1 declarations to publish one resolver result with stable function identity, provider incarnation, signature/default/direction metadata, retained implementation owner and explicit effects. **Entry and continuation slice.** Race current-policy publication against atomic entry admission using deterministic CalcDb scheduling, and capture native behavior where the host exposes an equivalent supported change. A revoked future invocation cannot run through a cached descriptor. An admitted active invocation retains its code; its nested calls acquire new permission. On return, invalidate only the dependencies the continuation needs. Reprepare pure physical work from accepted results, distinguish separate logical occurrences and preserve error/effect receipts through Close. No reentry waits on its own ancestor.

**Runtime-service slice.** Publish clock/random/database-context services with explicit state owners and inherited budgets. Exercise a domain/Eval child operation through the same COM/ISAM/query state, rather than an alternative object model. The adapter identifies the actual selected namespace and database context. Compare Windows COM, explicit host adapter and future portable stand-in lanes independently. A memory-safe retained result that belongs to a closed operation must still receive the correct public continuation outcome.

**Dependencies.** Actual foundation declarations and a minimal real host; no full SQL/DAO prerequisite. R-UDF-1 owns expression routing and reentry semantics; R-ADO-1 owns event ordering.
