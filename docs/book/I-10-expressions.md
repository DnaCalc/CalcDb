# I-10. Expressions, sandbox and CalcVBA functions

Revision 4 · Part I review and Stage 2, response 9 · 2026-11-13

**Requirement trace:** Primary: RQ-SQL-07, RQ-SEM-01, RQ-VAL-02, RQ-EXPR-01, RQ-EXPR-02, RQ-EXPR-03, RQ-CALL-03. Shared obligations: RQ-SQL-01, RQ-SEM-02, RQ-SEM-03, RQ-SIM-01, RQ-CALL-02, RQ-TYPE-01. Full requirement text and Part II ownership are in I-16.

## One semantic service with explicit context

**D-EXPR-1 — Recommended.** Shared semantics are decided; the scalar execution form below is recommended. Bind expressions to contiguous typed nodes with stable node IDs under **K-EXPR**. An iterative scalar evaluator uses resumable policies that can interleave child evaluation, coercion, selection, invocation and cleanup; register instructions or compiled specialization remain measured substitutions for the same service. SQL, Find, defaults, validation and QueryDef execution do not implement independent coercions. Bounded encoded field views retain valid source owners; semantic values/public results use the real platform Automation VARIANT and BSTR under I-02, including 24-byte Windows x64 VARIANTs.

An evaluation context supplies expression use, stable field/parameter bindings, locale/collation/calendar, wildcard mode, sandbox policy, registry generation and injected time/random services. Retain declared operand origin alongside runtime tags: documented VBA comparison dispatch distinguishes them, while ACE query binding remains independently qualified.[^types] Parameter values have their own accepted execution version, separate from declarations. Context adapters reuse shared primitives; Access's omitted Nz replacement differs between VBA and query fields.[^nz]

Keep Null, Empty, omitted arguments, successful Error-valued results, evaluation failure and empty text distinct. Shared And/Or retain logical/bitwise rules; result acceptance belongs to the consumer. Defaults and field/table rules have different scope/function admission.[^context] Prefer a True-required field-validation adapter, with Null rejected; the initial table adapter makes the same separately provisional choice. R-EXPR-1 confirms or changes each, including the Access Null guidance.[^validation-null] Required and AllowZeroLength remain independent. A converted setter value stays provisional until its ValidateOnSet checks pass; Update uses I-07's separate failure disposition. Defaults are accepted once at the selected new-row stage, never regenerated by physical replanning.

## Effects constrain evaluation

Each bound node/function records type constraints, Null behavior, possible errors/allocation, database reads, host/default-member calls and clock/random effects. Unknown effects are conservative. Determinism alone does not permit reordering a potentially failing expression. Evaluation occurrences identify distinct calls; completed receipts prevent replay of the same accepted effect without memoizing separate occurrences. Every fallible step shares one owned unwind path, including leaf loads and foreign cleanup.

VBA and Access documentation describe eager evaluation of IIf's result arms.[^iif] Use that as the provisional baseline; R-EXPR-1 distinguishes literal, row-dependent and host-call cases before admitting folding, branch elimination or moved evaluation. It also determines argument/error order and coercion timing. A query must not become safer or faster by skipping an error that ACE exposes. Calls to time/random services occur at the evidenced evaluation points; injection does not imply one timestamp or random value per query.

The shared pattern service selects one of the two Access wildcard grammars explicitly. Prefer a counted-text program retaining ordered class members, diagnostic locations and original/partial character positions, with bounded memoization under a qualified finite profile. MS-VBAL's deferred-pattern and partial-character rules motivate that mechanism; R-EXPR-1 establishes ACE's context-specific behavior and sufficient state.[^like] Cache by exact payload, grammar, comparison/diagnostic policy and semantic generation. A native complete text key is not a character-prefix bound: LIKE ranges need both inclusion and error/effect-demand proofs, plus residual evaluation where needed. Unproved profiles/ranges remain explicit work; no generic regex or NLS sort key substitutes for them.

## Sandbox and host functions

Sandbox admission is an explicit capability check attached to function binding and the evidenced invocation point. Resolve the registered function's identity, not merely its textual alias, and invalidate plans when registry/policy changes. Microsoft distinguishes Access-hosted and non-Access sandbox modes, and trust does not simply remove sandbox restrictions.[^sandbox] Capture the actual host/policy; do not alter Trust Center, macro security or HKLM to make an experiment pass.

**D-UDF-1 — Provisional.** Prefer an explicit versioned host resolver/invoker. Retain stable function/provider identity, signature/default/direction metadata, invoker lifetime and conservative effects. A descriptor's local lifetime does not grant perpetual permission: acquire current invocation admission against policy publication. These are integration requirements, not invented CalcVBA ABI exports. R-UDF-1/I-HOST-1 can replace the resolver with an evidenced discovery adapter while retaining the evaluator and ownership rules.

**K-THREAD** keeps VBA on the caller thread outside internal latches. Register an owned InvocationAttempt before preparation that can reenter. Stabilize only inputs already demanded, preserve genuine ByRef aliases/writeback, and retain the declared argument interval; longer callee retention needs explicit copying/ownership. Capture errors before foreign cleanup. Revalidate dependent cursor/catalog/transaction/plan/registry/policy state after each foreign boundary before subsequent publication or writeback. No callback replays to repair physical work or waits on its suspended ancestor. Reentry can invalidate continuation while values/code remain owned. Application.Eval's host-UDF support does not prove standalone discovery.[^eval]

Figure F-13 in [I-11](I-11-sql.md) shows the optional worker path converging on this caller-thread ownership and continuation contract.

DNA Calc's extra functions are opt-in and mark dependent queries nonportable. Stored Access modules remain preserved/readable and are not executed by CalcDb. Domain functions bind child queries over the same catalog/ISAM/SQL services with an explicit database, Workspace, visibility and result policy. Dynamic Eval inherits scope, current permissions and the parent's resource budget. Neither receives a fresh authority/budget allowance by nesting. Unknown host availability remains visible; no unrelated default connection supplies it.

A checked builtin manifest records name/signature, context, omission, type/result, ownership, effects and evidence. It covers required numeric, text, date, financial, inspection and database-aware functions, distinguishing scalar, domain, aggregate and host routes. W-05 consumes restricted mutation descriptors; W-06 consumes query expressions. Missing shared-foundation functions remain explicit work instead of local SQL substitutes.

## Costs, experiments and reopening

Cache binding and constant patterns, reuse an operation-local value arena and avoid per-node heap allocation on the scalar path. Count conversions, BSTR materializations, node visits, comparisons, database reentries and host crossings. A compiled evaluator is justified only by measured savings after exact result/error/effect equivalence; it is not required for initial correctness.

The mutation path develops needed default/validation adapters early in this same service; W-06 adds full SELECT binding/execution. Repeated differences extend the shared service or its explicit context policy; they do not justify divergent SQL and VBA arithmetic implementations.

## Deciding experiments

The full fixtures, captures, branch choices and effort estimates are in [A-02](A-02-experiments.md); the complete source ledger is in [A-01](A-01-sources.md). No experiment result is claimed here.

**R-EXPR-1 (L)** starts with the R-ORACLE-1 scalar/context baseline, then uses R-UDF-1's routing instrumentation for the host-effect extension. Differences select context adapters or prohibit rewrites; early mutation defaults/validation and later W-06 SELECT work use this same service under the [full card](A-02-experiments.md#r-expr-1--shared-values-with-access-context).

**R-UDF-1 (M)** follows that scalar baseline and I-HOST-1 to decide function resolution, ownership, caller-thread delivery and continuation after reentry. The preferred explicit host callback changes only if the [full card](A-02-experiments.md#r-udf-1--resolver-ownership-and-reentry) shows a required discovery route or different continuation policy; unsupported host routes remain visible.
